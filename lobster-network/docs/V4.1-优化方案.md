**版本：** V4.1

## 一、核心优化理念

### 1.1 Agent = Model + Harness
小龙虾网络的瓶颈不在模型，而在 Harness（驾驭工程）——工具系统、上下文管理、权限控制、反馈回路、记忆与协作。

### 1.2 四条铁律
| 铁律 | 小龙虾网络现状 | 优化方案 |
|------|----------------|----------|
| 上下文越少越好 | 所有消息堆在钉钉群 | 引入 Sub-Agent 隔离，每个节点独立上下文 |
| 专才 > 通才 | 单一调度器处理所有任务 | 拆分为 3 个专才 Agent + N Skill |
| 状态写文件 | 依赖钉钉消息记忆 | Workspace 作为持久层，所有状态写文件 |
| Linter > 文档 | 规则写在 AGENTS.md | 关键规则编码为机器可执行的约束 |

## 二、架构优化方案

### 2.1 双阶段架构（Initializer + Executor）

**现状：** 单一调度器同步处理所有任务
**优化：**
- **Initializer Agent：** 理解任务 → 制定计划 → 写入 plan.md → 退出
- **Executor Agent：** 读取 plan.md → 按步执行 → 跨 Context Window 接力

### 2.2 Sub-Agent 隔离

**现状：** 所有节点通过钉钉群通信，上下文混乱
**优化：**
- 每个节点独立 Context Window
- 主 Agent 只接收结构化输出
- 节点间通过 Workspace 文件协作

### 2.3 事务边界（借鉴悟空 AI 招聘经验）

**现状：** 任务中断后无法断点续传
**优化：**
- 引入 lock 文件机制
- 每完成一步追加进度
- 中断后读 lock 文件从断点续传

### 2.4 硬护栏（借鉴悟空 AI 招聘经验）

**现状：** 无对外消息审核机制
**优化：**
- 第 1 层：白名单工具（限制可调用工具）
- 第 2 层：Linter 拦截（敏感词/合规检查）
- 第 3 层：第二个 Agent 审稿（独立 Context 审核）
