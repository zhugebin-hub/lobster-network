01 / 为什么做

一个座位
有多难找？

😤
占座难题
一本书占座一整天，资源严重浪费
🔍
信息不对称
跑遍所有自习室，不知道哪里有空位
📋
管理困难
管理员无法实时掌握座位使用情况
⚖️
缺乏约束
没有信用机制，违约成本为零

02 / 系统架构

四层架构设计

📱 前端层：HTML + CSS + JavaScript
原生前端，零框架依赖
🔧 后端层：Flask + Flask-SocketIO
RESTful API + WebSocket 实时推送
💾 数据层：SQLAlchemy ORM
支持 SQLite / MySQL 无缝切换
⏰ 调度层：APScheduler
后台定时任务：超时释放 + 自动补位
Flask SQLAlchemy SocketIO APScheduler QR Code

🔔
实时通知
SocketIO 推送预约、候补、信用变动

05 / 管理端

全方位管控能力

1
统计分析看板 — 座位使用率、热门时段、热门区域可视化
2
实时座位总览 — 按自习室/区域/状态筛选，一键释放异常占用
3
自习室管理 — 添加/编辑自习室，批量生成座位网格
4
规则配置 — 每日预约次数、签到宽限、信用阈值等 11 项参数
5
信用管理 — 查看信用记录，手动调整分值
6
举报审核 — 审核违规占座举报，通过后自动扣分并释放座位
7
CSV 导出 — 预约数据一键导出，操作日志全程留痕

06 / 亮点

信用积分体系

100
初始信用分
+1
正常签到签退
-10
超时未签到
-20
违规占座

信用分 低于 60 无法预约

连续违约 3 次 冻结预约权限

形成"守约受益、违约受惩"的良性循环

⚡

08 / 自动化

后台定时调度

⏰
每 60 秒 自动扫描超时预约
已确认未签到 → 超时释放 + 扣信用分
🔄
自动候补补位
预约释放后，候补队列第一人自动获得座位
📝
预约结束自动签退
预约时间到达后自动标记完成，触发候补补位

APScheduler 后台调度器 · 可配置间隔 · 支持热更新
