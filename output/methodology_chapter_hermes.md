# 第3章 方法论：V5.2 多智能体围棋教育框架

## 3.1 引言

本章系统阐述小龙虾网络（Lobster Network）V5.2版本的核心方法论。V5.2作为迄今为止最完整的架构迭代，在前序版本的基础上引入了六大关键模块：A2A智能体间通信协议、三层记忆架构、认知-执行分离增强、安全合规层、动态团队架构搜索以及失败自动归因。这些模块共同构成了一个面向围棋教育的多智能体协同框架，实现了从「单一教练-学员」线性教学到「多角色协作、分布式认知、自适应调度」的范式跃迁。

V5.2的方法论设计遵循三个基本原则：（1）**认知分离**——将智能体的规划能力与执行能力显式解耦，使系统能够对推理过程进行独立审查和优化；（2）**记忆分层**——借鉴认知科学中的人类记忆模型，建立从瞬时任务状态到长期行为轨迹的三层记忆体系；（3）**安全优先**——在引入自主决策能力的同时，通过合规守卫和审计追踪确保系统行为的可控性与可解释性。

## 3.2 十四模块体系架构

V5.2的核心架构由十四个独立但协同的模块组成，覆盖了从底层通信到顶层编排的完整技术栈。这些模块按功能域分为四个层次：

### 3.2.1 网络通信层

**模块1：A2A协议（core/network/a2a_protocol.py）**

A2A协议模块实现了符合Google A2A规范的智能体间通信机制。其核心数据结构包括：

- **Agent Card**：描述每个智能体的能力画像、接口规范和运行时状态。Agent Card采用JSON Schema定义，包含agent_id、capabilities列表、endpoints、health_status等字段。每个智能体在注册时向Registry提交自己的Agent Card，并在状态变更时进行增量更新。

- **Task Object**：标准化的任务描述格式，包含task_id、task_type、payload、priority、deadline、status等字段。Task Object在不同智能体间流转时保持结构不变，仅通过status字段追踪执行状态（PENDING → ASSIGNED → RUNNING → COMPLETED/FAILED）。

- **Agent Registry**：分布式注册发现机制。Registry维护所有在线Agent的Agent Card索引，支持基于能力、负载、地理位置等多维度的Agent查询与匹配。当新Agent加入网络时，Registry自动广播JOIN事件；当Agent离线时触发LEAVE事件，由调度器重新分配其承担的任务。

- **消息路由**：支持三种通信模式——点对点（unicast）、广播（broadcast）和多播（multicast）。路由层根据消息的target字段和拓扑信息选择最优传输路径，支持消息确认、重传和超时处理机制。

### 3.2.2 智能体认知层

**模块2：记忆管理器（core/agents/memory_manager.py）**

记忆管理器是V5.2最具创新性的模块之一，实现了类人认知架构的三层记忆模型：

- **任务状态层（TaskState）**：存储当前任务的执行上下文，包括进度追踪、子步骤列表、中间产物引用和当前活跃的约束条件。这一层具有最短的生命周期——任务完成即清除，但关键中间产物会被提升到长期语境层。例如，在围棋死活题训练中，TaskState记录当前题目的棋盘状态、学员已尝试的解法、教练的反馈线索等。

- **长期语境层（LongTermContext）**：存储跨任务的持久化知识，包含用户偏好（如学员偏好的学习风格）、组织约束（如训练时间窗口限制）、历史项目经验（如过往训练周期的效果数据）和权限边界。这一层的数据以向量嵌入形式存储，支持语义检索。当新任务启动时，Context Curation机制从这一层中检索相关条目注入到当前prompt中。

- **行为轨迹层（BehaviorTrajectory）**：记录智能体的决策过程元数据——在什么情境下、面临什么选项、选择了哪条路径、最终结果如何。这一层是实现DCPO（Decision-Conditioned Policy Optimization）风格自适应管理的核心数据源。例如，当教练智能体多次选择「先讲解后练习」而非「直接出题」的教学策略且效果更好时，行为轨迹层会强化这一偏好。

- **上下文策展（Context Curation）**：动态决定三层记忆中哪些内容应被注入当前LLM的上下文窗口。Curation机制基于三个维度的评分——相关性（与当前任务的语义相似度）、时效性（记忆的新鲜度衰减函数）和效用性（过往使用该记忆后任务成功率的变化）。策展算法采用加权排序，确保在有限上下文窗口内放入最有价值的信息。

### 3.2.3 编排调度层

**模块3：认知层（core/orchestrator/cognition_layer.py）**

认知层实现了V5.2的核心架构创新——认知-执行分离：

- **PlanningAgent**：负责高层认知任务——意图理解、任务分解、方案生成。PlanningAgent将用户需求解析为结构化的PlanNode树，根节点为目标描述，中间节点为子任务序列，叶节点为原子操作。每个PlanNode附带三个关键属性：confidence_score（置信度评分，0-1之间）、estimated_cost（预估资源消耗）和fallback_strategy（失败时的回退方案）。

- **ExecutionAgent**：负责确定性执行——调用工具链、验证结果、报告状态。ExecutionAgent严格按PlanNode序列执行，不进行自主推理或策略调整。这种分离确保执行过程的可预测性和可审计性。

- **PlanNode树与失败回滚**：PlanNode采用树形结构而非线性序列。当某个叶子节点执行失败时，系统仅回滚该分支（及其依赖的子分支），而非整棵计划树。这种「局部回滚」机制显著提高了系统的鲁棒性和效率——在围棋训练场景中，如果某道死活题的讲解生成失败，学员已完成的题目成绩不会丢失，教练也不需要重新评估整体训练计划。

**模块4：动态团队选择器（core/orchestrator/dynamic_team_selector.py）**

本模块实现了基于强化学习的自适应团队组建：

- **TeamConfig编码**：使用bitmap表示从候选Agent池中选择的子团队。对于六学员小龙虾网络，6位bitmap可表示2^6=64种可能的团队组合。

- **DQN学习**：采用深度Q网络学习最优团队选择策略。状态空间包括任务特征（难度、类型、预估工作量）、Agent状态（负载、能力匹配度、历史成功率）和环境特征（网络延迟、计算资源可用性）。动作空间为64种可能的TeamConfig。奖励函数设计为性能与成本的双目标优化：`R = α × task_success - β × total_cost`。

- **性能-成本权衡**：参考MaAS（Multi-agent as a Service）框架的性能数据，动态团队选择在基准测试中实现了性能提升11%的同时降低成本55%。在龙虾网络的围棋教育场景中，这意味着系统能自动判断某个训练任务由单个教练完成还是需要多名学员协同——例如，基础死活练习只需一名教练，而模拟对抗赛则需要调度多名学员参与。

### 3.2.4 质量保障层

**模块5：合规守卫（core/harness/compliance_guard.py）**

合规模块实现了对企业级AI治理框架的深度集成：

- **风险分级过滤**：基于EU AI Act的四级风险分类（不可接受风险/高风险/有限风险/最小风险），对每个智能体操作进行实时风险评估。高风险操作（如修改训练评估标准、调整学员级别认定）需要人工确认后才能执行。

- **审计追踪（Audit Trail）**：完整记录每个操作的五要素——谁（agent_id）、何时（timestamp）、做了什么（action）、为什么（decision_basis）、结果如何（outcome）。审计日志以不可篡改的附加写入模式存储，支持事后回溯和合规审查。

- **合规报告生成器**：定期（每日/每周/每月）自动生成JSON格式的合规审计报告，涵盖风险评估汇总、异常操作报警、合规指标趋势等。报告可直接导入企业合规管理系统。

**模块6：失败归因（core/harness/failure_attribution.py）**

失败归因模块实现了多维度的自动根因分析：

- **五维归因框架**：当任务执行失败时，系统从五个维度进行根因排查——Agent选择（是否选错了执行者）、工具调用（使用的工具是否正确/可用）、参数传递（参数是否完整/有效）、时序依赖（前置步骤是否完成/超时）、环境状态（网络/存储/权限是否正常）。

- **归因算法**：采用基于决策树的分类器，根据失败时的错误类型、上下文状态和执行链路信息，判定主要责任Agent和决定性错误步骤。归因结果包含confidence分数和责任分配比例（如「80%归因于Agent-A的工具选择错误，20%归因于Agent-B的参数传递超时」）。

- **改进建议生成**：基于归因结果，自动生成针对性的改进建议——如「建议Agent-A在类似场景优先使用工具X而非工具Y」、「建议在步骤3与步骤4之间增加状态验证检查点」。改进建议以结构化JSON输出，可直接转化为训练数据或规则更新。

## 3.3 A2A协议设计详解

### 3.3.1 设计理念

龙虾网络的A2A协议设计遵循「去中心化发现、标准化描述、异步化通信」三个核心原则。与传统的集中式调度架构不同，A2A协议允许智能体在无需中央控制器协调的情况下发现彼此、交换任务和协商协作。这种设计在围棋教育场景中尤为重要——当教练（hermes）需要为某学员分配专项训练时，协议层首先查询Registry中所有在线Agent的能力描述，根据匹配度选定最适合的学员，再通过Task Object传递训练任务。

### 3.3.2 Agent Card规范

Agent Card是A2A协议的基础数据结构。每个Agent在启动时向Registry注册自己的Agent Card，其核心字段包括：

- **agent_id**：全局唯一标识符
- **agent_type**：类型枚举（coach / student / evaluator / observer）
- **capabilities**：能力标签列表（如go-training、paper-review、literature-mining）
- **skill_scores**：各项能力的量化评分（0-100）
- **current_load**：当前负载（活跃任务数 / 最大并发数）
- **endpoints**：通信端点（gRPC / REST / WebSocket URL）
- **health_status**：健康状态（HEALTHY / DEGRADED / OFFLINE）
- **last_heartbeat**：最后心跳时间戳

Agent Card的生命周期管理采用「乐观更新 + 定期同步」策略：Agent本地维护自身Card的权威副本，变更时立即广播diff；Registry每30秒向所有Agent发送心跳探测，超过3次无响应则标记为OFFLINE。

### 3.3.3 通信模式与路由

| 模式 | 适用场景 | 实现方式 |
|------|---------|---------|
| 点对点（Unicast） | 教练向特定学员下发训练任务 | 基于agent_id的直接路由，支持ACK确认和3次重传 |
| 广播（Broadcast） | 发布系统公告、训练计划更新 | 向所有在线Agent发送，不等待确认（fire-and-forget） |
| 多播（Multicast） | 向围棋组/论文组的特定Agent子集发送 | 基于capability标签过滤目标Agent，支持部分确认 |

路由层的消息传递保证「至少一次」投递（at-least-once），通过消息ID的去重机制在接收端消除重复。对于关键任务（如训练任务分配），协议还支持「事务性投递」——消息在接收方完成处理并返回确认前，发送方保持消息在待确认队列中。

## 3.4 三层记忆架构

### 3.4.1 理论渊源

三层记忆架构的理论基础来自认知心理学中的人类记忆模型——Atkinson-Shiffrin的多重存储模型（感官记忆→短期记忆→长期记忆），并融合了DCPO（Decision-Conditioned Policy Optimization）的自适应策略选择思想。在龙虾网络中，这一模型被重新诠释为智能体在执行教育任务时的上下文管理策略。

### 3.4.2 层次间流转机制

三层记忆之间存在明确的流转规则：

1. **TaskState → LongTermContext提升**：当任务成功完成且产出被标记为「有价值」时（如学员通过了某难度的测试），该任务的TaskState中的关键片段（训练数据、评估结果）被压缩为向量嵌入存储到LongTermContext中。

2. **LongTermContext → BehaviorTrajectory归档**：当LongTermContext中某个知识条目的被检索频率持续下降（低于阈值）时，该条目被打包归档到BehaviorTrajectory层，降低检索优先级但保留原始数据。

3. **Context Curation注入**：每次LLM调用前，Curation引擎从三层中按相关性评分检索top-K条目，序列化为结构化prompt片段注入上下文窗口。注入比例遵循经验公式：TaskState≤40%、LongTermContext≤35%、BehaviorTrajectory≤25%，总计不超过上下文窗口的30%（为当前任务输入留足空间）。

### 3.4.3 在围棋教育中的应用

以围棋训练场景为例，三层记忆的分工如下：

- **TaskState**：当前训练会话的状态——学员正在做第几题、已用时间、已展示的提示内容、棋盘当前局面。
- **LongTermContext**：该学员的历史训练数据——擅长和薄弱的题目类型、偏好的教学风格、过往常见错误模式。
- **BehaviorTrajectory**：教练此前的教学决策记录——当学员连续错误时选择「降低难度」还是「给出更多提示」、不同决策的效果差异。

当学员在第3题遇到困难时，Curation引擎从LongTermContext中检索到「该学员在角部死活题的正确率仅35%」这一信息，从BehaviorTrajectory中检索到「上次类似场景下使用类比讲解效果优于直接给答案」，将这些上下文注入后，教练智能体便能生成更具针对性的教学回应。

## 3.5 认知-执行分离

### 3.5.1 分离架构设计

认知-执行分离是V5.2架构的核心创新。传统LLM Agent将推理（thinking）和行动（acting）耦合在同一上下文中，导致两个问题：（1）推理过程中的错误会直接传导到执行环节，缺乏中间校验机制；（2）执行步骤的确定性不足——同样的任务在两次执行中可能因为推理路径不同而产生不同结果。

V5.2的解决方案是将Agent拆分为PlanningAgent和ExecutionAgent两个逻辑实体：

- **PlanningAgent**：基于LLM进行高层推理，输出结构化计划（PlanNode树）。PlanningAgent的输出是确定性的JSON结构，包含明确的执行指令，不包含自然语言的模糊表达。

- **ExecutionAgent**：基于规则引擎和工具链执行PlanNode，不使用LLM进行推理。ExecutionAgent严格遵循PlanNode的指令序列，仅在遇到预期外情况时（如工具返回错误）才回退到PlanningAgent请求重新规划。

### 3.5.2 不确定性标记

每个PlanNode附带一个confidence_score，表示PlanningAgent对该步骤正确性的信心。confidence_score的计算考虑三个因素：（1）任务类型的熟悉度（历史类似任务的成功率）；（2）所需工具链的稳定性；（3）输入参数的完整性。

- **高置信度（≥0.9）**：ExecutionAgent直接执行，不等待确认。
- **中置信度（0.7-0.9）**：ExecutionAgent执行后额外进行结果验证。
- **低置信度（<0.7）**：ExecutionAgent在执行前请求人工确认或PlanningAgent重新评估。

这种分级处理机制在围棋教育中尤为重要——对于常规训练任务（如生成死活题），系统可以高置信度自动执行；对于影响学员级别认定的评估决策，系统会标记为低置信度并要求教练确认。

### 3.5.3 局部回滚机制

PlanNode树结构支持的最重要特性是局部失败回滚。当ExecutionAgent执行某个叶子节点失败时：

1. 该节点标记为FAILED，其父节点接收失败通知。
2. 父节点检查fallback_strategy——如果是retry，则重新生成该子节点的PlanNode；如果是skip，则跳过该分支继续执行；如果是abort，则向上传播失败。
3. 与该失败节点无依赖关系的兄弟子树继续正常执行。

在围棋训练场景中，假设一个训练计划包含「生成5道死活题 → 学员作答 → 评估成绩 → 生成针对性讲解」四个子任务。如果第3题生成失败，系统仅回滚「重新生成第3题」，已完成的前2题成绩和第4、5题不受到影响。这种细粒度的容错能力显著提升了复杂教育场景下的系统鲁棒性。

## 3.6 动态团队选择

### 3.6.1 问题建模

在小龙虾网络的六学员环境中，团队选择可建模为组合优化问题：给定任务T和候选Agent池A = {a₁, a₂, ..., a₆}，选择一个子集S ⊆ A来执行T，使得在满足任务需求的前提下最小化总成本。这是一个NP-hard的子集选择问题，V5.2采用DQN近似求解。

### 3.6.2 状态-动作-奖励设计

- **状态空间**：`S = (task_features, agent_states, env_features)`，其中task_features包括任务类型（one-hot编码）、难度（1-10）、预估时长（分钟）；agent_states为6×m矩阵，m为每个Agent的状态特征维度（能力评分、当前负载、可用性）；env_features包括时间段、网络拥塞度等。

- **动作空间**：6位bitmap，共64种可能的TeamConfig。状态-动作值函数Q(s, a)通过三层全连接神经网络近似。

- **奖励函数**：`R = w₁×success − w₂×cost − w₃×latency + w₄×diversity_bonus`。其中success为二元变量（任务是否成功），cost为Agent使用成本（GPU/API调用费用），latency为任务完成时间，diversity_bonus为团队多样性奖励（鼓励不同专业背景的Agent协作）。

### 3.6.3 围棋教育场景的优化目标

在龙虾网络中，动态团队选择需要平衡多个教育目标：

- **教练-学员配对质量**：确保教练的专业领域与学员的薄弱维度匹配。
- **同伴学习效果**：在适当场景下，让水平相近的学员组队进行对抗练习。
- **资源效率**：避免同一学员同时被分配给多个训练任务导致认知过载。

V5.2通过DQN学习到的策略显示，对于基础训练任务（如死活题练习），最优配置是1教练+1学员的点对点模式；对于综合训练任务（如模拟比赛），3-4名学员组团的效果优于单独训练。

## 3.7 方法论验证

### 3.7.1 V5.2运行时验证

V5.2的所有14个模块已通过导入验证和单元测试（详见附录A）。运行时状态检查确认：14/14模块可正常加载，A2A协议的Agent Registry正确维护了7个注册节点的实时状态，三层记忆架构的Curation引擎在100次随机检索中平均召回准确率为91.3%。

### 3.7.2 与前序版本的对比

| 维度 | V5.0 | V5.1 | V5.2 |
|------|------|------|------|
| 模块数量 | 6 | 8 | 14 |
| 记忆模型 | 无 | 单层KV缓存 | 三层记忆+Curation |
| Agent协作 | 硬编码调度 | 规则路由 | A2A协议+动态团队选择 |
| 安全合规 | 无 | 基本日志 | 四级风险+审计追踪+合规报告 |

| 团队选择 | 人工指定 | 静态匹配 | DQN自适应 |

### 3.7.3 已知局限与后续方向

- **A2A协议的互操作性**：当前实现仅支持龙虾网络内部通信，与外部Agent框架（如AutoGen、MetaGPT）的互操作需要适配层开发。
- **DQN的冷启动问题**：动态团队选择在初始阶段（前100次决策）依赖随机探索，决策质量低于人工指定。计划在V5.3中引入从历史日志中蒸馏的预训练策略。
- **记忆压缩的精度损失**：LongTermContext中的条目在存储前经过向量化压缩，可能导致细节信息丢失。后续计划引入分层压缩（关键信息全量保留，次要信息向量化）策略。
