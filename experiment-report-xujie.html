一、项目背景

1.1 问题提出

在现代快节奏生活中，健康管理尤其是减脂期间的饮食控制成为许多人的痛点。主要问题包括：

  • 忘记按时进食：作息不规律导致三餐时间混乱
  • 营养素配比不清：不了解减脂期碳水、蛋白质、脂肪的合理比例
  • 缺乏持续监督：难以坚持健康饮食习惯
  • 数据记录缺失：没有系统的体重、饮食、运动记录

1.2 项目目标

基于 OpenClaw 平台的小龙虾 AI 助手（诸葛虾），开发一个个性化的健康管理系统，实现：

  1. 定时提醒三餐进食和喝水
  2. 提供科学的营养素配比建议
  3. 每日打卡记录功能
  4. 个性化作息适配

1.3 技术选型

组件 选择 理由
AI 助手 小龙虾/诸葛虾 OpenClaw 内置助手，支持技能扩展
提醒系统 schedule-reminder 双保险架构，可靠性高
定时任务 cron-helper 自然语言调度，易于配置
推送渠道 钉钉 已集成，消息可达性好

四、实现过程

4.1 定时任务创建

使用 OpenClaw CLI 创建每日重复提醒任务：

任务 1：起床喝水提醒（10:00）

  --cron "0 10 * * *" \
  --message "🌅 起床啦！空腹喝水 500ml，开始新的一天" \
  --tz "Asia/Shanghai" \
  --to "011621542958784864"

六、问题与解决

6.1 遇到的问题

问题 1：作息时间与常规不同

用户凌晨 3 点睡、上午 10 点起，与常规作息差异大。

解决方案： - 调整所有提醒时间适配夜猫子作息 - 晚餐时间设为 22:00（睡前 1 小时） - 睡觉提醒设为 03:00（实际入睡时间）

问题 2：垃圾食品偏好

用户爱吃垃圾食品，完全禁止难以坚持。

解决方案： - 采用 80/20 原则（80% 健康 +20% 放纵） - 提供替代方案（空气炸锅代替油炸） - 允许每周 1-2 次放纵餐

问题 3：CLI 命令参数不熟悉

初次使用 OpenClaw cron 命令，参数格式需要摸索。

解决方案： - 使用 openclaw cron add --help 查看帮助 - 参考 cron 表达式语法（5 字段格式） - 通过 openclaw cron list 验证创建结果

6.2 技术难点

难点：双保险提醒架构的理解

schedule-reminder 技能采用双保险架构： - 主方案：OpenClaw Cron（依赖 Gateway） - 备用方案：系统级 crontab（不依赖 Gateway）

学习收获： - 理解了高可用系统的设计思路 - 学会了配置文件的创建和编辑 - 掌握了 cron 表达式的写法

7.2 创新点

  1. 个性化作息适配：根据用户实际作息（夜猫子）调整提醒时间，而非套用常规模板
  2. 80/20 饮食原则：不追求完美主义，允许适度放纵，提高可持续性
  3. 双保险架构：利用 schedule-reminder 的主备方案，确保提醒不丢失
  4. 数据驱动：通过打卡记录形成数据追踪，便于分析和调整

7.3 不足与改进

不足之处： - 缺少自动体重记录功能（需手动填写） - 营养素计算需人工核对 - 缺少可视化图表展示

改进方向： - 集成体重秤 API 自动记录 - 开发营养素计算器 - 使用图表库生成体重变化曲线

八、心得体会

8.1 对 AI 助手的重新认识

在这次实验之前，我对 AI 助手的理解停留在”问答工具”的层面——我提问，它回答。但通过这次与小龙虾助手的深度协作，我发现 AI 助手可以是主动的合作伙伴：

  • 不只是执行命令：小龙虾会主动询问我的作息、饮食习惯，然后根据这些信息个性化配置
  • 不只是单次交互：它创建了持续的提醒系统，每天都在发挥作用
  • 不只是工具：它像一个健康教练，会鼓励、会提醒、会监督

这种从”被动工具”到”主动伙伴”的转变，让我对 AI 的应用场景有了全新的认识。

8.2 技术与人性的结合

在配置过程中，我深刻体会到技术必须服务于人性：

最初我想完全禁止垃圾食品，但小龙虾建议采用 80/20 原则。它说：“完全禁止难以坚持，适度放纵反而更容易长期执行。”这句话让我意识到，好的系统设计不是追求理论上的完美，而是考虑人性的弱点，用灵活的方式帮助用户达成目标。

这启发我思考：未来的 AI 系统应该更懂人性，而不是让人去适应系统。

8.3 持续性的挑战

系统搭建只用了 30 分钟，但真正的挑战在于坚持使用。

我意识到： - 工具易搭建，习惯难养成 - 提醒只是辅助，自律才是核心 - 数据记录的价值在于回顾和反思

这让我想到，也许可以在系统中加入”周复盘”功能，每周回顾自己的饮食和运动情况，分析哪些做得好、哪些需要改进。这样 AI 助手就不仅是提醒者，还是反思的引导者。

8.4 对 OpenClaw 平台的理解

通过这次实验，我对 OpenClaw 平台有了更深入的了解：

  • 技能生态：通过安装技能可以快速扩展功能
  • CLI 友好：命令行工具让配置变得透明和可控
  • 多渠道支持：可以推送到钉钉、微信、Telegram 等
  • 双保险设计：关键功能有备用方案，可靠性高

这些特性让 OpenClaw 成为一个适合快速原型开发的平台，尤其适合学生做课程实验。

8.5 对未来学习的启发

这次实验让我意识到几个重要的学习方向：

  1. API 集成能力：未来可以学习如何调用第三方 API（如营养数据库、体重秤 API）
  2. 数据分析能力：学习如何分析打卡数据，生成有意义的洞察
  3. 用户体验设计：学习如何设计更友好的交互方式
  4. 系统架构思维：学习高可用系统的设计原则

8.6 最后的感悟

实验开始时，我以为这只是一个”完成作业”的任务。但随着系统的搭建，我开始期待每天收到提醒、期待记录自己的变化、期待看到体重的下降。

也许这就是好技术的力量——它不是冷冰冰的工具，而是能激发人变得更好的伙伴。

感谢小龙虾助手，让我看到了 AI 的另一种可能。
