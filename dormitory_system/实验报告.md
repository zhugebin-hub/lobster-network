# 新生选寝系统实验报告

## 一、实验目的

开发一套智能化的新生宿舍分配系统（业务小龙虾版），实现以下目标：

1. 基于学生问卷数据（性别、生源地、作息习惯、抽烟、游戏偏好等）进行智能宿舍匹配
2. 支持室友意向绑定（强意向自动优先组合）
3. 提供多维度冲突检测（性别不一致、抽烟底线冲突、极端作息冲突等）
4. 支持手动调整（移动、互换、挂起）与版本管理
5. 提供智能体对话式操作与可视化 Web UI 双入口
6. 导出标准化 Excel 分配结果

## 四、核心算法设计

### 4.1 匹配算法概述

系统采用启发式匹配算法，结合硬约束过滤与软评分排序，实现多目标优化的宿舍分配。

### 4.2 分池策略

- 按性别分为男寝池和女寝池
- 男寝编号从 101 开始，女寝编号从 201 开始
- 每间寝室默认 4 人（可配置）

### 4.3 并查集强意向绑定

从问卷的"意向室友"字段和"备注"字段中识别学生姓名或学号，构建并查集（Union-Find）数据结构，将强意向绑定学生优先分配到同一寝室。

```
强意向绑定流程：
  1. 解析意向字段 → 提取姓名/学号对
  2. 构建并查集 → 合并同一连通分量
  3. 按连通分量大小降序排序
  4. 依次将每个连通分量分配到寝室
```

### 4.4 硬约束（阻止同住）

| 约束类型 | 说明 |
|----------|------|
| 性别不一致 | 不同性别学生不能同住 |
| 抽烟底线冲突 | 不抽烟 + 反感抽烟 vs 抽烟学生 |
| 极端作息冲突 | 早睡（22:00 前）vs 晚睡（01:00 后） |

### 4.5 软评分体系

系统通过加权评分选择最优室友组合，分数越低越匹配：

| 评分项 | 权重 | 说明 |
|--------|------|------|
| 意向同住 | -5000 | 最强正向信号 |
| 作息差异 | 差异值 × 100 | 作息时间相差越大分数越高 |
| 游戏偏好差异 | 差异值 × 18 | 游戏习惯不匹配程度 |
| 噪音敏感 | +45 | 噪音敏感学生额外惩罚 |
| 本科同校 | -14 | 同一本科院校纽带加分 |
| 本科同城 | -10 | 同一城市本科院校纽带加分 |
| 生源同乡 | -5 | 同一生源地纽带加分 |
| 本地/本校带动 | 负向加分 | 本地学生带动外地学生 |

### 4.6 挂起池处理

未能完全填满的寝室中的剩余学生进入"混寝挂起池"，系统建议按同校/同城/同乡纽带进行外调捆绑处理。

## 五、关键实现

### 5.1 数据导入与校验

系统支持 xlsx/csv/tsv 三种格式的数据导入：

- **官方名单**（必填）：学号、姓名、性别、生源地
- **问卷表**（可选）：手机号、本科院校、意向室友、生活习惯（抽烟、作息、游戏、噪音、卫生、空调、午睡、社交、饮食）、备注

导入时自动校验字段完整性，缺少学号时自动生成 NOID-行号 作为主键。

### 5.2 敏感信息脱敏

对手机号进行掩码处理（仅显示后 4 位），健康备注等特殊信息仅在必要时展示，符合数据隐私保护要求。

### 5.3 API 鉴权

支持两种鉴权方式：

- Authorization: Bearer Token
- X-API-Key

Token 存储于 .api_tokens 文件中，支持多 Token 管理。

### 5.4 版本管理

每次匹配或调整后，系统支持：

- 保存当前方案为命名版本（JSON 文件持久化）
- 列出所有历史版本及时间戳
- 恢复任意历史版本

版本文件存储于 versions/ 目录，支持跨会话、跨设备访问。

### 5.5 冲突检测与风险提示

每次生成方案或调整后，系统自动检测并标记：

- ⚠️ 性别不一致
- ⚠️ 抽烟底线冲突
- ⚠️ 极端作息冲突
- ⚠️ 备注回避同住

同时展示纽带关系：

- 🔗 本科同校
- 🔗 本科同城
- 🔗 生源同乡
- 🔗 本地/本校带动

### 5.6 Excel 导出

导出文件包含三张工作表：

1. **寝室分配结果**：寝室号、学号、姓名、性别、生源地等
2. **混寝挂起池**：待处理学生列表
3. **学生画像**：学生完整生活习惯与偏好

## 八、系统部署

### 8.1 部署方式

#### 方式一：直接运行

```bash
cd /home/admin/.openclaw/workspace/dormitory_system
python3 server.py
```

#### 方式二：部署脚本

```bash
bash deploy.sh start    # 启动
bash deploy.sh stop     # 停止
bash deploy.sh restart  # 重启
bash deploy.sh status   # 查看状态
bash deploy.sh test     # 运行测试
```

#### 方式三：Docker

```bash
docker compose up -d
```

#### 方式四：systemd

```bash
sudo cp dormitory-system.service /etc/systemd/system/
sudo systemctl enable dormitory-system
sudo systemctl start dormitory-system
```

### 8.2 持久化运行

- crontab @reboot 开机自启
- 每 5 分钟心跳检查，自动重启异常进程
- 日志记录于 logs/server.log

### 8.3 智能体集成

系统作为"业务小龙虾"注册到多智能体协作网络：

- 能力描述文件：/shared/capabilities/lobster-dorm-001.json
- 路由桥接器：dorm_bridge.py
- 技能文档：skills/dormitory-lobster/SKILL.md

管理员可通过钉钉对话直接操作选寝系统。

## 十、实验总结

本实验成功开发了一套功能完整的新生选寝系统，实现了从数据采集、智能匹配、冲突检测到手动调整和版本管理的全流程自动化。

### 10.1 主要成果

1. **核心算法**：基于并查集 + 硬约束 + 软评分的启发式匹配算法，在 100 人真实数据测试中达到 100% 强意向绑定成功率
2. **双入口设计**：同时支持 Web UI 可视化操作和智能体对话式操作
3. **生产级部署**：支持 Docker、systemd、crontab 多种部署方式，具备开机自启和心跳监控能力
4. **数据安全**：API 鉴权 + 敏感信息脱敏，保障学生隐私
5. **版本管理**：跨会话、跨设备的方案版本持久化

### 10.2 技术亮点

- 使用 Python 标准库实现 HTTP 服务，零框架依赖
- email.parser 替代已废弃的 cgi 模块，兼容 Python 3.12+
- 并查集数据结构高效处理强意向绑定
- 多维度加权评分实现多目标优化
- 响应式前端设计，无需任何前端框架

### 10.3 后续改进方向

| 优先级 | 改进方向 |
|--------|----------|
| 高 | 钉钉入口深度集成（用户直接在钉钉对话排寝） |
| 中 | 算法升级为约束求解（OR-Tools）优化全局最优 |
| 中 | 数据库替换 JSON 文件存储（PostgreSQL/SQLite） |
| 低 | 微信小程序作为用户入口 |
| 低 | 多方案对比功能（A/B/C 方案并排展示） |
