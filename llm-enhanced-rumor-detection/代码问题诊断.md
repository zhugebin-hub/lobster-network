## 问题 1：Phase 1 的 evaluate 用的是未训练的 aggregation 模块

### 代码位置

**`src/training/trainer.py` 第 142-157 行**：

```python
def validate_epoch(self, phase: int = 1) -> Dict[str, float]:
    """Validate for one epoch."""
    self.model.eval()
    epoch_losses = []

    with torch.no_grad():
        for batch_data in tqdm(self.val_loader, desc='Validation'):
            batch_data = self._move_to_device(batch_data)
            outputs = self.model(batch_data)
            losses  = self.model.compute_loss(outputs, batch_data, phase=phase)
            epoch_losses.append(losses['total_loss'].item())

    loss_metric = {'loss': np.mean(epoch_losses) if epoch_losses else 0.0}
    eval_metrics = self.evaluate(self.val_loader)  # ← 这里调用 evaluate
    loss_metric.update(eval_metrics)
    return loss_metric
```

```python
def predict(self, batch_data: Dict) -> Dict[str, torch.Tensor]:
    """Make predictions without gradients."""
    self.eval()
    with torch.no_grad():
        outputs = self.forward(batch_data)
        rumor_probs = outputs['rumor_probs']  # ← 这是 aggregation 的输出
        rumor_class = torch.argmax(rumor_probs, dim=-1)
        ...
```

### 问题分析

1. **Phase 1 训练时**：
   - 优化的是 `binary_rumor_probs`（K 个 binary classifier 的输出）
   - aggregation 模块的参数**完全没有更新**（因为 Phase 1 只训练 encoder + binary classifiers）

2. **Validation 时**：
   - `evaluate()` 调用 `model.predict()`
   - `predict()` 用的是 `outputs['rumor_probs']`
   - 这个 `rumor_probs` 是 **aggregation 模块的输出**
   - 而 aggregation 在 Phase 1 时参数是**随机初始化的**

3. **结果**：
   - Phase 1 的前 8 个 epoch，evaluate 时用的是**随机 aggregation**
   - 所以准确率接近随机水平（0.33 ≈ 随机猜测）

## 问题 2：Phase 1 的 loss 设计不合理

### 代码位置

**`src/models/llm_enhanced_mil.py` 第 189-200 行**：

```python
if phase == 1:
    # --- Eq.12: BCE per binary classifier ---
    binary_rumor_probs = outputs['binary_rumor_probs']  # K scalars
    phase1_loss = torch.tensor(0.0, device=device)
    for k in range(self.num_binary_classifiers):
        target_r, _ = self.binary_classifiers.get_target_class_pair(k)
        y_k = float(rumor_label == target_r)
        prob_k = binary_rumor_probs[k].clamp(_EPS, 1.0 - _EPS)
        bce_k = -(y_k * torch.log(prob_k) + (1.0 - y_k) * torch.log(1.0 - prob_k))
        phase1_loss = phase1_loss + bce_k
    losses['phase1_loss'] = phase1_loss
    losses['total_loss']  = phase1_loss
```

### 问题分析

1. **每个 binary classifier k 对应一个 (rumor_class, stance_class) 对**：
   - classifier 0: (rumor=0, stance=0)
   - classifier 1: (rumor=0, stance=1)
   - classifier 2: (rumor=0, stance=2)
   - classifier 3: (rumor=0, stance=3)
   - classifier 4: (rumor=1, stance=0)
   - classifier 5: (rumor=1, stance=1)
   - classifier 6: (rumor=1, stance=2)
   - classifier 7: (rumor=1, stance=3)

2. **Phase 1 的 loss 计算**：
   - 对于一个 rumor_label=0 的样本
   - classifier 0, 1, 2, 3 的 target 都是 1（因为 rumor_label == 0）
   - classifier 4, 5, 6, 7 的 target 都是 0（因为 rumor_label != 1）

3. **问题**：
   - **Phase 1 的 loss 完全没有用到 stance 信息**
   - 只是让每个 classifier 学习："当前样本的 rumor_label 是否等于我的 target_rumor_class"
   - 这不是在学习立场分类，只是在学习一个简化的二分类任务
   - 而且这个任务的定义方式可能不够有效

## 🎯 根本原因总结

准确率只有 0.33 的根本原因：

1. ✅ **Phase 1 的 evaluate 用的是未训练的 aggregation 模块**
   - aggregation 参数是随机的
   - 所以输出接近随机

2. ✅ **Phase 1 的 loss 设计不合理**
   - 没有用到 stance 信息
   - 只是在学习一个简化的二分类任务

3. ✅ **训练了 8 个 epoch，但都是 Phase 1**
   - aggregation 一直没训练
   - 所以 evaluate 一直是随机输出

4. ✅ **这不是训练慢的问题，而是训练逻辑有严重缺陷**

## 📊 预期行为 vs 实际行为

### 预期行为

- Phase 1：训练 encoder + binary classifiers，准确率逐渐上升
- Phase 2：训练 aggregation，准确率进一步提升

### 实际行为

- Phase 1：训练 encoder + binary classifiers，但 **evaluate 时用的是随机 aggregation**
- 结果：准确率一直接近随机（0.33）

---

## ✅ 解决方案

### 方案 1：修改 Phase 1 的 evaluate 逻辑（推荐）

让 Phase 1 的 evaluate 也用 binary_rumor_probs，而不是 aggregation 的输出。

具体做法：
- 在 `predict()` 里增加一个 `phase` 参数
- Phase 1 时，用 binary_rumor_probs 的平均值或投票来预测
- Phase 2 时，用 aggregation 的输出

### 方案 2：让 Phase 1 也训练 aggregation（不推荐）

这违背了论文的两阶段训练设计。

### 方案 3：只看 Phase 2 的准确率（临时方案）

Phase 1 的准确率不重要，只要 Phase 2 的准确率正常就行。

但这需要至少跑到 Phase 2（第 200 个 epoch 之后），学弟现在才跑到第 8 个 epoch。

---

## 🔧 我的建议

2. **让 Phase 1 的准确率也能正确反映模型效果**
3. **缩短 Phase 1 的 epoch 数**（当前已改为 10）

## 📝 补充说明

### 为什么是 0.33 而不是 0.5？

对于二分类，随机猜测应该是 0.5。但这里是 0.33，可能原因：

1. **数据不平衡**：如果数据集里 rumor=0 的样本占 67%，那么随机猜测的准确率就是 0.67 或 0.33
2. **aggregation 的随机初始化偏向某一类**：随机参数可能导致输出偏向某一类
3. **评估时的某些 bug**：比如预测和标签的对齐问题

但核心问题还是：**Phase 1 的 evaluate 用的是未训练的 aggregation 模块**。

---

**总结：这不是训练慢的问题，而是训练逻辑有严重缺陷。需要修复 Phase 1 的 evaluate 逻辑。**
