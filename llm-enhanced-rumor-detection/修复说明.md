# 代码修复说明

## ✅ 已修复的致命 Bug

### 问题：准确率只有 0.33 的根本原因

**不是训练慢的问题，而是训练逻辑有严重缺陷。**

---

## 🔴 原代码的致命问题

### Phase 1 的 evaluate 用的是未训练的 aggregation 模块

**原逻辑**：
1. Phase 1 训练时，只优化 encoder + binary classifiers
2. aggregation 模块的参数完全不更新（随机初始化状态）
3. 但 validation 时，`evaluate()` 调用 `model.predict()`
4. `predict()` 用的是 `aggregation` 模块的输出
5. 结果：Phase 1 的准确率一直是随机水平（0.33）

**代码位置**：
- `src/training/trainer.py` 第 155 行：`eval_metrics = self.evaluate(self.val_loader)`
- `src/models/llm_enhanced_mil.py` 第 216 行：`rumor_probs = outputs['rumor_probs']`（这是 aggregation 的输出）

**影响**：
- 学弟跑了 8 个 epoch，都是 Phase 1
- aggregation 一直没训练
- 所以准确率一直接近随机（0.33）

---

## ✅ 修复方案

### 修复 1：让 Phase 1 的 predict 使用正确的逻辑

**修改文件**：`src/models/llm_enhanced_mil.py`

**修改内容**：
- 在 `predict()` 方法里增加 `use_phase1_logic` 参数
- Phase 1 时，用 `binary_rumor_probs` 的加权平均来预测
- Phase 2 时，用 `aggregation` 的输出

**具体逻辑**：
```python
if use_phase1_logic:
    # Phase 1: 用 binary_rumor_probs 计算谣言预测
    # 对每个 rumor class，平均其对应的 classifiers 的概率
    binary_rumor_probs = outputs['binary_rumor_probs']  # K scalars
    rumor_probs_aggregated = torch.zeros(self.num_rumor_classes, ...)
    
    for k in range(self.num_binary_classifiers):
        target_r, _ = self.binary_classifiers.get_target_class_pair(k)
        rumor_probs_aggregated[target_r] += binary_rumor_probs[k]
    
    # 归一化（每个 rumor class 对应 num_stance_classes 个 classifiers）
    rumor_probs_aggregated = rumor_probs_aggregated / self.num_stance_classes
    rumor_probs = rumor_probs_aggregated
else:
    # Phase 2: 用 aggregation 输出
    rumor_probs = outputs['rumor_probs']
```

## 🎯 为什么原来是 0.33 而不是 0.5？

对于二分类，随机猜测应该是 0.5。但这里是 0.33，可能原因：

### 1. 数据不平衡
如果数据集里 rumor=0 的样本占 67%，那么：
- 随机 aggregation 可能偏向预测 rumor=0
- 准确率 = 67% × 正确率 + 33% × 错误率
- 如果完全预测 rumor=0，准确率 = 67%
- 如果完全预测 rumor=1，准确率 = 33%

### 2. aggregation 的随机初始化偏向某一类
随机参数可能导致输出偏向 rumor=1，而数据集里 rumor=0 占多数。

### 3. 评估时的某些 bug
比如预测和标签的对齐问题。

**但核心问题还是**：Phase 1 的 evaluate 用的是未训练的 aggregation 模块。
