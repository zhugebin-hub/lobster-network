## 核心理念

**不是从零开始写PPT，而是从已有的对话和文件中"收割"素材。**

传统做法：临到汇报才收集素材 → 赶工 → 一次性材料
本技能做法：日常对话即沉淀 → 定期收成 → 迭代式产品

## 工作流程：四步法

### 第一步：素材扫描（Scanning）

扫描工作区中所有相关材料，建立素材清单：

```bash
# 按关键词搜索相关文件
find ~/.openclaw/workspace -type f \( -name "*.md" -o -name "*.pptx" -o -name "*.docx" \) \
  | xargs grep -l -i "关键词1\|关键词2\|关键词3" 2>/dev/null

# 按时间范围查看近期产出
find ~/.openclaw/workspace -type f -newer /path/to/reference-file \
  \( -name "*.md" -o -name "*.pptx" \) -exec ls -lah {} \;

# 读取关键文件的内容，提取核心信息
cat /path/to/key-document.md
```

**需要扫描的素材类型：**
| 类型 | 说明 | 示例 |
|------|------|------|
| 教学案例 | 已归档的案例文档 | teaching_cases/ 目录 |
| 项目总结 | 阶段性总结文档 | *总结*.md / *情况总结*.md |
| 往期PPT | 已有PPT的内容结构 | *.pptx |
| 方案文档 | 企业培训方案等 | *培训方案*.md |
| 聊天记录 | 钉钉导出的对话案例 | dingtalk-case-export/ |
| 数据记录 | 量化指标、统计数据 | 日志、报告 |
| 用户反馈 | 真实使用体验 | memory/ 日志中的反馈 |

### 第二步：叙事提炼（Framing）

**这是最关键的一步——找到好的叙事角度。**

常见叙事框架（根据汇报场景选择）：

| 框架 | 适用场景 | 核心结构 |
|------|---------|---------|
| **历史对比法** | 推广、立项汇报 | 过去教训 → 现在做法 → 未来路径 |
| **成果展示法** | 阶段性总结 | 做了什么 → 效果如何 → 下一步 |
| **问题解法** | 需求论证 | 痛点 → 解决方案 → 验证结果 |
| **故事叙述法** | 经验分享 | 起点 → 转折 → 突破 → 启示 |
| **产品迭代法** | 产品/项目更新 | v1 → v2 → v3 → 未来路线图 |

**叙事提炼原则：**
1. ✅ 从痛点出发，不谈技术谈价值
2. ✅ 用具体数字说话（节省多少时间、覆盖多少人）
3. ✅ 加入真实用户故事（人物+转变+成果）
4. ✅ 有明确的行动号召或下一步计划
5. ❌ 不要做成技术说明书

### 第三步：内容编排（Structuring）

标准汇报PPT结构（10-15页）：

```
封面
  ↓
目录
  ↓
背景/为什么做（1-2页）
  ↓
我们做了什么（2-3页）—— 核心成果展示
  ↓
效果如何（1-2页）—— 数据+案例
  ↓
方法论/经验总结（1-2页）—— 可复制的部分
  ↓
下一步/行动计划（1页）
  ↓
总结页（金句收尾）
  ↓
结束页/感谢
```

**每页设计原则：**
- 标题 = 观点，不是标签（"先吃透自己的场景" 比 "推广策略" 好）
- 一页一个核心信息
- 用图标/表格/流程图代替大段文字
- 关键数字放大突出

### 第四步：PPT 生成（Producing）

使用 python-pptx 或 open-slide 生成 PPT 文件：

```python
# python-pptx 示例
from pptx import Presentation
from pptx.util import Inches, Pt, Emu
from pptx.enum.text import PP_ALIGN
from pptx.dml.color import RGBColor

prs = Presentation()
prs.slide_width = Inches(13.333)  # 16:9 宽屏
prs.slide_height = Inches(7.5)

slide = prs.slides.add_slide(prs.slide_layouts[6])  # 空白布局

# 添加标题
txBox = slide.shapes.add_textbox(Inches(1), Inches(2.5), Inches(11.333), Inches(1.5))
tf = txBox.text_frame
p = tf.paragraphs[0]
p.text = "标题文字"
p.font.size = Pt(36)
p.font.bold = True
p.alignment = PP_ALIGN.CENTER

prs.save("output.pptx")
```

## 多智能体协作模式

当有诸葛马（Hermes）等协作节点时，采用交叉验证：

```
虾尔（主生成）                    诸葛马（审校）
    │                                │
    ├── 1. 扫描素材 → 生成初稿 ──────┤
    │                                ├── 2. 独立审读 → 提出修改建议
    │                                ├── 3. 补充视角（遗漏的角度）
    │                                ├── 4. 验证数据准确性
    │                                │
    ├── 5. 整合反馈 → 修订版 ────────┤
    │                                │
    └── 6. 输出最终版 ←──────────────┘
```

**质量提升点：**
- 两个智能体独立review，避免单一视角的盲区
- 诸葛马可以从"读者角度"检查：信息是否清晰、逻辑是否通顺
- 虾尔负责执行：素材整理、PPT生成、格式调整

## 量化数据积累指南

**从第一次汇报开始，建立数据追踪：**

| 指标 | 记录方式 | 频率 |
|------|---------|------|
| 使用次数 | 在 memory/ 日志中记录 | 每次使用后 |
| 节省时间 | 让用户反馈或估算 | 每周汇总 |
| 覆盖人数 | 使用智能体的用户数 | 每月统计 |
| 任务类型 | 记录处理的任务类别 | 每次记录 |
| 用户满意度 | 收集用户原话反馈 | 每次使用后 |

记录模板（写入 memory/YYYY-MM-DD.md）：
```markdown
## 📊 小龙虾使用数据
- 今日使用次数：X
- 节省时间估算：X 小时
- 处理任务类型：[课表转换/论文指导/...]
- 用户原话反馈："..."
```

## 迭代式产品思维

每次生成的PPT不是终点，而是产品版本：

```
v1.0 初版 → 收集反馈 → v1.1 修订 → 再次使用 → 收集反馈 → v2.0 重大更新
```

**版本管理：**
- 文件名带版本号或日期：`XXX汇报_v1.0_20260609.pptx`
- 每次修订记录变更内容
- 保留历史版本，方便回溯
