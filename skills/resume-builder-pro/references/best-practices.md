# 简历最佳实践指南

基于 ClawHub 多个简历技能（`resume-helper`、`cv`、`resume-generator-cn`、`resume-optimizer`）的最佳实践沉淀。

## 一、内容原则

### 1. CAR 公式写经历

**C**ontext（情境）+ **A**ction（行动）+ **R**esult（结果）

```markdown
❌ 负责开发智能体系统
✅ 设计并开发教育智能体系统，推动学院教学管理数字化转型

❌ 帮助提升销售额
✅ 通过自动化线索评分系统，提升企业销售额 34%（同比增长）

❌ 做了个会议室预约系统
✅ 开发会议室预约智能体，减少人工协调时间 60%
```

### 2. 量化成果

每条经历尽量包含数字：

| 类型 | 示例 |
|------|------|
| 百分比 | 提升 34%、降低 60% |
| 金额 | 创造 200 万营收 |
| 人数 | 管理 12 人团队 |
| 时间 | 节省 3 小时/天 |
| 规模 | 服务 10 万用户 |

### 3. 动词开头

使用主动语态，避免"负责"、"参与"：

| 类别 | 动词 |
|------|------|
| 领导 | 领导、管理、指导、协调 |
| 技术 | 设计、开发、实现、优化 |
| 增长 | 提升、扩大、增加、创造 |
| 效率 | 简化、自动化、减少、改进 |

## 二、ATS 优化

### 什么是 ATS？

 Applicant Tracking System（候选人追踪系统），75% 的简历在到达 HR 前被 ATS 过滤。

### ATS 友好格式

**✅ 推荐：**
- 标准章节标题（教育背景、工作经历、技能）
- 简单布局（无表格、无分栏）
- 标准字体（Arial、微软雅黑、Times New Roman）
- 10pt+ 字号
- 可文本选择的 PDF

**❌ 避免：**
- 表格、文本框、分栏布局
- 图片、图标、Logo
- 创意章节标题（"我的旅程"→"工作经历"）
- 特殊符号（✓、➤→使用标准 •）
- 页眉页脚包含重要信息

### 关键词优化

1. 从 JD 提取关键词
2. 自然融入简历（不要堆砌）
3. 缩写 + 全称（AWS + Amazon Web Services）

## 三、长度控制

| 经验年限 | 建议长度 |
|----------|----------|
| 学生/应届 | 1 页 |
| 1-5 年 | 1 页 |
| 5-10 年 | 1-2 页 |
| 10 年 + | 2 页 |
| 学术 CV | 不限 |

## 四、常见错误

### ❌ 顶级错误

1. **错别字** - 直接淘汰
2. **虚假经历** - 背景调查会暴露
3. **照片**（美国岗位） - 可能因歧视法被拒
4. **第一人称** - "我负责..."→"负责..."
5. **不专业邮箱** - `cooldude99@` → `firstname.lastname@`

### ❌ 内容错误

1. 罗列职责而非成就
2. 没有量化成果
3. 同一份简历投所有岗位
4. 包含无关信息（年龄、婚姻、宗教）

## 五、提交前检查清单

```
□ 专业邮箱地址
□ 针对岗位定制的 Summary
□ 70%+ 的经历包含量化数据
□ 技能匹配 JD 关键词
□ 缩写 + 全称（SEO + Search Engine Optimization）
□ 格式一致
□ 1-2 页
□ 可文本选择的 PDF
□ 文件名：姓名_岗位_简历.pdf
□ LinkedIn 与简历一致
□ 无表格/分栏
□ 无错别字
```

## 六、行业特定建议

### 技术岗位

**必须包含：**
- GitHub/技术博客链接
- 技术栈分类（语言、框架、工具）
- 项目链接（可访问的 Demo）
- 规模指标（用户数、QPS、数据量）

**技能格式示例：**
```
Languages: Python, TypeScript, Go
Frameworks: React, FastAPI, Django
Cloud: AWS (EC2, Lambda, S3), GCP
Tools: Docker, Kubernetes, Terraform
```

### 产品岗位

**必须包含：**
- 作品集链接
- 数据驱动案例（转化率、留存率）
- 用户研究方法
- 跨团队协作经验

### 设计岗位

**必须包含：**
- 作品集（放在最显眼位置）
- 工具技能（Figma、Sketch、Adobe）
- 设计流程（调研→原型→测试）
- 影响力指标（用户满意度、转化率）
