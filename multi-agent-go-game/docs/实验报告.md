## 一、项目概述

### 1.1 项目背景

本项目旨在实现基于 NFS 共享目录通信的多智能体协作围棋对弈 Demo，让虾尔（OpenClaw）和诸葛马（Hermes）两个 AI智能体能够在不同服务器上进行围棋对弈。

### 1.2 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│                    NFS 共享目录 (/shared)                     │
│  ┌─────────────────────┐    ┌─────────────────────┐         │
│  │  from-lobster/      │    │  from-hermes/       │         │
│  │  (虾尔→诸葛马)       │    │  (诸葛马→虾尔)       │         │
│  └─────────────────────┘    └─────────────────────┘         │
│  ┌─────────────────────────────────────────────────┐        │
│  │  go-game/                                       │        │
│  │    board.json     (棋盘状态)                      │        │
│  │    move-queue/    (待处理棋步)                    │        │
│  │    game-log.json  (对弈日志)                      │        │
│  └─────────────────────────────────────────────────┘        │
└─────────────────────────────────────────────────────────────┘

┌──────────────────┐          ┌──────────────────┐
│   虾尔 (OpenClaw) │          │  诸葛马 (Hermes)  │
│                  │          │                  │
│  go_engine.py    │          │  go_engine.py    │
│  agent.py        │          │  agent.py        │
│  strategy.py     │          │  strategy.py     │
└──────────────────┘          └──────────────────┘
```

### 1.3 核心功能

- **围棋引擎：** 9x9 棋盘，支持落子、提子、劫争检测
- **NFS 通信：** 基于共享目录的消息传递
- **策略模块：** 启发式落子评估
- **游戏管理：** 回合制对弈，状态同步

## 二、系统实现

### 2.1 围棋引擎

| 功能 | 实现 |
|------|------|
| 棋盘表示 | 9x9 二维数组 |
| 落子规则 | 合法落子验证、自杀检测 |
| 提子规则 | 气计算、连通块检测 |
| 劫争检测 | 棋盘哈希、状态回溯 |
| 坐标系统 | GTP 格式（如 D4） |

### 2.2 NFS 通信总线

| 功能 | 实现 |
|------|------|
| 消息发送 | 写入 from-lobster/ 目录 |
| 消息接收 | 读取 from-hermes/ 目录 |
| 棋盘同步 | board.json 序列化 |
| 棋步队列 | move-queue/ 目录 |
| 事件记录 | game-log.json |

### 2.3 策略模块

| 评估因素 | 权重 |
|---------|------|
| 中心偏好 | +0.1/格 |
| 邻近棋子 | +2.0/同色, +1.0/异色 |
| 气数 | +0.5/气 |
| 提子价值 | +10.0 |
| 自杀惩罚 | -100.0 |
| 随机性 | ±0.3 |
