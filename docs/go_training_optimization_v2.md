## 三、优化方案

### 3.1 方案一：统一训练提交路径（解决 P0-问题 2）

**目标**：建立统一的训练结果提交规范，消除路径不一致导致的监控误报。

**实施**：
- ✅ 创建 `submit_training.py` 标准脚本
- ✅ 统一提交到 `.shared/training/go/from-{node_id}/`
- ✅ 保留 `docs/training_results/` 作为镜像
- ✅ 自动处理路径、格式验证、git 提交

**使用示例**：
```bash
python3 core/submit_training.py \
  --domain go \
  --day 5 \
  --results ./output/day5_result.json \
  --node-id qoder
```

### 3.2 方案二：自动化训练执行器（解决 P0-问题 1）

**目标**：为每个节点创建可自主运行的训练执行器，解决节点参与率极低的根本问题。

**实施**：
- ✅ 创建 `train_executor.py`
- ✅ 自动检测新任务
- ✅ 执行训练流程，生成标准化 JSON 结果
- ✅ 通过 submit_training.py 自动提交
- ✅ 支持断点续传

**架构设计**：
```
每个节点一个 train_executor 实例
  ↓
通过 cron 定时触发（每 4 小时）
  ↓
执行器状态写入 .shared/training/go/executor_status/{node_id}.json
```

### 3.3 方案三：路径自适应与版本兼容（解决 P0-问题 3）

**目标**：消除所有硬编码路径，提升跨平台兼容性。

**实施**：
- ✅ 创建 `compat.py` 兼容层
- ✅ 所有脚本使用 `Path(__file__).resolve().parent` 自动检测路径
- ✅ `capture_output` 替换为 `stdout=subprocess.PIPE, stderr=subprocess.PIPE`
- ✅ 统一 Python 依赖声明

**关键改动**：
```python
# Replace:
BASE_DIR = '/home/admin/lobster-network'

# With:
BASE_DIR = Path(__file__).resolve().parent.parent
```

### 3.4 方案四：交叉审查机制（解决 P1-问题 5）

**目标**：引入 Harness Engineering 的"智能体审智能体"模式，确保训练质量可独立验证。

**实施**：
- ✅ 创建 `review_agent.py`
- ✅ 节点 A 的训练结果由节点 B 审查
- ✅ 审查者只看结果数据和规则文件（独立 Context）
- ✅ 审查结果写入 `.shared/reviews/go/{reviewer}_{reviewee}_{day}.json`
- ✅ 综合评分 = 自评分 × 0.4 + 交叉审查分 × 0.6

**审查轮转分配**：
| 训练者 | 审查者 |
|--------|--------|
| qoder | 小龙虾 |
| 小龙虾 | 小陈 |
| 小陈 | qoder |

### 3.5 方案五：真实对弈引擎（解决 P1-问题 6）

**目标**：替换随机模拟，接入真实围棋引擎，确保训练效果可量化验证。

**规划**：
- 集成 GNU Go 或 Leela Zero 作为对弈引擎
- 训练任务包含实际对局：与 AI 引擎下棋并记录 SGF
- 棋力评估基于真实对局胜率，非随机数
- 分级对弈：入门级 (9 路盘) → 进阶级 (13 路盘) → 高级 (19 路盘)

**实施路径**：
- 轻量级：调用 `gnugo --mode gtp` 通过 GTP 协议对弈
- 标准级：使用 kata-go 预训练模型
- 结果记录为标准 SGF 格式，可供人类复盘

### 3.6 方案六：通信机制升级（解决 P1-问题 7、8）

**目标**：增强 CC 协议的可靠性，降低通信故障率。

**实施**：
- ✅ 创建 `safe_git.py` 安全 Git 封装
- ✅ 自动处理 rebase/conflict
- ✅ 消息发送增加重试机制（最多 3 次，间隔指数退避）
- ✅ 引入消息去重：基于 message_id 的幂等处理
- ✅ 监控脚本改用统一的 check_status.py

**safe_git.py 核心功能**：
- Auto stash → pull --rebase → pop → push
- Conflict auto-resolution (prefer theirs for shared files)
- Token refresh mechanism
- Retry with exponential backoff

### 3.7 方案七：端到端健康检查（解决 P2-问题 9-12）

**目标**：建立系统级健康监控，及时发现并解决问题。

**实施**：
- ✅ 创建 `health_check.py`
- ✅ 定期检测各节点心跳是否正常
- ✅ 训练任务是否按时提交（对比 task 发布时间与 submit 时间）
- ✅ CC 消息 ACK 是否超时（>24h 未 ACK 告警）
- ✅ 仓库同步状态（git fetch 检查落后 commit 数）
- ✅ 健康报告写入 `.shared/health_report.json`
- ✅ 异常自动通过 CC 消息通知诸葛马

## 七、总结

本优化方案针对小龙虾网络围棋学习系统的现状进行了全面诊断，识别出 12 个关键问题，并按优先级分为 P0、P1、P2 三个等级。

**核心理念**："治本而非治标"：
- 统一训练提交路径和自动化执行器解决节点参与率极低的根本问题
- 交叉审查机制和真实对弈引擎确保训练质量可信、可验证
- 通信机制升级和健康检查保障系统长期稳定运行

**实施进度**：
- ✅ Phase 1：基础修复（submit_training.py, compat.py）
- ✅ Phase 2：可靠性提升（train_executor.py, review_agent.py, safe_git.py, health_check.py）
- 📅 Phase 3：质量保障（go_engine.py, lobster_daemon.py）
- 📅 Phase 4：稳定运行

**预期效果**：
通过 12 周的分阶段实施，预期将节点参与率从 20% 提升至 80% 以上，训练完成率从 25% 提升至 75% 以上，实现小龙虾网络围棋学习的全面优化。

**Agent 是工人，Session 才是工作本身。Harness Engineering 让 Agent 可控地工作。** 🦞
