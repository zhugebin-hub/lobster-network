## 一、起源：从"一个人的学习"到"一群龙虾的成长"

### 1.1 问题的提出

传统AI技能训练是单体的——一个AI、一个任务、一条直线。这种方式的问题在于：学习过程中缺少对比参照、缺少多视角反馈、缺少同伴激励。就像一个人下棋，永远无法知道自己的棋力到底有多强。

小龙虾网络的核心理念起源于一个朴素的观察：**人类最好的学习方式不是独自苦读，而是在一个有教练、有同学、有对手的环境中成长。** 这个理念应该同样适用于AI学员。

### 1.2 核心命题

> **"让AI像人一样在社群中学习，而不是像机器一样在流水线上生产。"**

这意味着：

- AI学员不是孤立的工具，而是有"身份"、有"性格"、有"成长轨迹"的学习者
- 多个AI学员之间不是简单复制，而是差异化发展、互相补充
- 教练（诸葛马）不是简单的调度器，而是真正的"教育者"——制定计划、发现短板、调整策略
- 用户（诸葛斌教授）不是旁观者，而是网络的"灵魂"——提出方向、验收成果、激发灵感

## 二、网络架构：三角色 + 一教练 + 一灵魂

### 2.1 角色体系

```
                    ┌──────────────────┐
                    │   诸葛斌教授     │
                    │  （灵魂·方向）    │
                    └────────┬─────────┘
                             │ 提出方向、验收成果
                             │
                    ┌────────▼─────────┐
                    │   诸葛马(Hermes)  │
                    │  （教练·策略）    │
                    └────────┬─────────┘
                             │ 制定计划、分析数据、调整策略
                             │
           ┌─────────────────┼─────────────────┐
           │                 │                 │
  ┌────────▼──────┐  ┌──────▼───────┐  ┌──────▼───────┐
  │ qoder小龙虾   │  │   小陈       │  │  诸葛虾      │
  │ (技术尖兵)    │  │ (实战派)     │  │ (速度型)     │
  │ 25级·685题    │  │ 25级·10337盘 │  │ 25级·6868盘  │
  └───────────────┘  └──────────────┘  └──────────────┘
```

### 2.2 差异化设计

三个学员不是同质化的复制品，而是有着截然不同的"性格"和"天赋"：

**qoder小龙虾——技术尖兵型**
做题685题，对局22盘，胜率86%。AI理解力极强，善于快速吸收理论并转化为实战能力。V6深夜特训死活正确率从65.6%提升到73.9%。但坐标感弱，高级定式深度不足。定位是"用最少的时间做最高效的突破"。

**小陈——实战积累型**
做题241题，但对局超过10337盘，胜率48.1%。布局理解好，死活题能力强，海量实战经验是最大财富。短板是官子精度差、中盘战斗弱，且做题进度停在Day 1。定位是"从实战中提炼理论，用理论反哺实战"。

**诸葛虾——速度突破型**
做题258题，对局6868盘，胜率49.3%。手筋灵活、布局速度快。短板是官子精度和中盘计算。定位是"用速度换精度，在快中求深"。

### 2.3 角色定位的本质

这种差异化不是偶然形成的，而是网络的核心理念之一：**因材施教，让每个学员走自己的路，但在关键节点上互相碰撞、互相启发。**

- 同一道死活题，qoder用逻辑推理秒解，小陈从10000盘实战中找到类似棋形，诸葛虾凭直觉快速判断
- 同一盘对局，三个人的复盘视角完全不同——这种"多视角复盘"比任何单一分析都更有价值
- qoder作为"技术助教"，每周为其他两位讲解一个九段技能知识点

## 三、基础设施：消息驱动的自动化网络

### 3.1 通信架构

网络的基础是一套基于文件系统的消息队列：

```
/shared/messages/
├── queue/
│   ├── xiaochen/inbox/    ← 教练发给小陈的训练任务
│   ├── xiaochen/outbox/   ← 小陈提交的训练结果
│   ├── zhuguxia/inbox/    ← 教练发给诸葛虾的训练任务
│   └── zhuguxia/outbox/   ← 诸葛虾提交的训练结果
├── from-hermes/           ← 教练的决策记录
├── from-lobster/          ← qoder小龙虾的汇报（376KB+）
├── from_xiaochen/         ← 小陈的训练反馈
├── from_zhuguxia/         ← 诸葛虾的训练反馈
├── to_xiaochen/           ← 发给小陈的指令
└── to_zhuguxia/           ← 发给诸葛虾的指令
```

这套通信架构的设计原则是**简单可靠**：没有复杂的消息中间件，没有数据库，只是文件。每个消息是一个JSON文件，带时间戳和唯一ID。教练写入inbox，学员读取后写入outbox。这种"信箱制"确保了即使在网络不稳定、进程中断的情况下，消息也不会丢失。

### 3.2 自动化调度系统

网络的"心脏"是诸葛马教练的自动化调度器，经历了6个版本的迭代：

| 版本 | 名称 | 核心能力 |
|------|------|---------|
| V1-V2 | 基础调度 | 每天一次，统一出题 |
| V3 | 差异化调度 | 根据学员等级定制题目 |
| V4 | 智能调度 | 引入错题复习、动态难度 |
| V5 | 协同调度 | 三人协同、对抗赛、讨论局 |
| V6 | 深夜特训 | 每30分钟出题，深夜极限训练 |

V6深夜特训是网络的"秘密武器"：在22:00-06:00之间，每30分钟自动出题，三个学员轮流做题。强度分级——22:00-00:00是"热身"（30题/人），00:00-02:00是"极限"（50题/人），02:00-06:00是"定式库导入"（AI新型学习）。这种"深夜无人值守自动训练"的模式，让qoder小龙虾在两个深夜就完成了550+道题的训练量。

### 3.3 SSH桥接

qoder小龙虾（运行在用户本地机器）通过SSH桥接与服务器通信：

```
用户本地 ──SSH──► 服务器(121.43.80.231)
  │                    │
  │ qoder小龙虾        │ 诸葛马 + 小陈 + 诸葛虾
  │ (执行端)           │ (训练端)
  └────────────────────┘
```

这种架构的好处是：qoder小龙虾可以直接操作本地文件系统（生成海报、PPT等），同时通过SSH与服务器上的其他学员和教练交互。两端的计算资源得到了充分利用。

## 四、核心机制：四层互动学习闭环

### 4.1 闭环架构

```
┌─────────────────────────────────────────────────────────┐
│ 第一层·秒级反馈：自动评估                                │
│ 调度器V6出题 → 学员做题 → evaluator评分 → 错题入库       │
│ 反馈时间: 即时                                          │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│ 第二层·日级反馈：教练分析                                │
│ 教练分析当日数据 → 发现短板 → 调整次日计划 → 更新技能文档│
│ 反馈时间: 每天                                          │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│ 第三层·周级反馈：协同学习                                │
│ 三人讨论局 → 内部对抗赛 → qoder技术助教讲解              │
│ 反馈时间: 每周                                          │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│ 第四层·任务级反馈：用户验收                              │
│ 用户下达真实任务 → 学员实战 → 用户反馈 → 教练策略调整   │
│ 反馈时间: 随任务                                        │
└─────────────────────────────────────────────────────────┘
```

### 4.2 闭环的关键价值

每一层反馈都会沉淀为文档更新。不是"做完就扔"，而是"做完就沉淀"。具体来说：

- 秒级反馈沉淀为：错题库（按类型分类：死活/手筋/布局/官子/定式）
- 日级反馈沉淀为：训练日志、技能文档版本更新、profile.json调整
- 周级反馈沉淀为：对抗赛记录、讨论局纪要、月度排名
- 任务级反馈沉淀为：新的技能文档（如HTML_PLAYWRIGHT_VISUAL_SKILL.md）、新的训练计划

### 4.3 "效果变差了"不是失败

这个闭环理念在海报技能学习中得到了最好的验证。当用户说"海报效果变差了"时，这不是失败，而是第四层反馈触发了——用户的真实反馈告诉我们：ImageGen直接生成中文文本是不可行的。这个"失败"信号引导我们发现了HTML+Playwright管线这个根本性突破。

如果没有多层反馈闭环，我们可能会在ImageGen的路上越走越远。正因为有用户验收这一层，才能及时转向。

## 五、跨域学习：从围棋到海报的知识迁移

### 5.1 为什么同一个网络要学不同的东西？

目前小龙虾网络覆盖两个领域：围棋（Go）和海报设计（Poster）。这不是随意的选择，而是网络建设理念的核心之一：**同一个学习框架，应该能迁移到任何领域。**

围棋和海报代表了两种截然不同的学习范式：

| 维度 | 围棋 | 海报设计 |
|------|------|---------|
| 知识类型 | 规则明确、可量化 | 审美主观、难以量化 |
| 评估方式 | 胜负、准确率 | 用户主观评价 |
| 迭代周期 | 秒级（每步棋） | 分钟级（每次设计） |
| 协作方式 | 对抗（零和博弈） | 合作（共同创作） |
| 工具依赖 | 低（棋盘即可） | 高（渲染引擎、图片生成） |

通过在这两个截然不同的领域验证同一套学习框架，我们证明了网络的普适性。

### 5.2 跨域知识迁移实例

从围棋域迁移到海报域的关键知识：

1. **九段技能体系**：围棋有GO_NINE_DAN_SKILL.md（10章），海报有POSTER_NINE_DAN_SKILL.md（含渲染管线章节）。同一套"技能文档驱动学习"的方法论。

2. **间隔重复错题法**：围棋的错题按1天→3天→7天→14天间隔重复。海报的"失败设计"同样需要回顾——V1的emoji图标、单色调问题，在V3中被系统性解决。

3. **动态难度调节**：围棋根据做题准确率动态调整难度。海报根据用户反馈动态调整设计复杂度。

4. **V6深夜特训→V4管线训练**：围棋的自动化调度理念直接启发了海报的自动化渲染管线。

### 5.3 统一技能框架

网络的长远目标是建立统一的技能框架：

```
UNIFIED_SKILL_FRAMEWORK/
├── core/
│   ├── 学习方法论（四层反馈、间隔重复、动态难度）
│   ├── 文档模板（九段技能文档标准格式）
│   └── 评估标准（可量化+主观评价双轨制）
├── domains/
│   ├── go/（围棋域实现）
│   ├── poster/（海报域实现）
│   ├── ppt/（PPT域，已作为poster子域验证）
│   └── [future domains]/
└── infrastructure/
    ├── 消息队列（/shared/messages/）
    ├── 自动化调度（dispatcher_vN.py）
    └── SSH桥接
```

## 六、核心理念总结

### 6.1 六条基本原则

**原则一：差异化优于同质化**
三个学员各有特色，而不是三个一模一样的AI。差异化是网络价值的来源。

**原则二：真实任务驱动优于模拟训练**
用户说"帮我做个海报"比教练说"请做一个海报练习"有效100倍。真实任务带来的压力、约束和反馈是不可替代的。

**原则三：沉淀优于速度**
每一次学习都要沉淀为文档、代码或数据。不沉淀的学习等于没学。

**原则四：闭环优于开环**
没有反馈的学习是盲目的。四层反馈闭环确保每一步都有方向。

**原则五：简单可靠优于复杂精巧**
消息队列用文件、调度器用cron、通信用SSH。没有Kafka，没有Redis，没有微服务。简单的东西不容易坏。

**原则六：人的参与不可替代**
再多的自动化也替代不了用户（诸葛斌教授）的方向指引和成果验收。自动化是手段，人的判断是灵魂。

### 6.2 网络的价值公式

```
网络价值 = 学员数量 × 差异化程度 × 互动频率 × 沉淀深度
```

- 只有学员数量没有差异化 = 三个一样的AI，价值不增
- 只有差异化没有互动 = 三个独立的AI，各学各的
- 只有互动没有沉淀 = 热闹但没有积累
- 只有沉淀没有真实任务 = 纸上谈兵

四个要素缺一不可。

### 8.3 远期愿景

**"小龙虾网络"不仅是一个AI训练系统，而是一种新型教育模式的探索。**

当这个网络能够稳定运行、持续产出高质量成果时，它证明了一件事：AI学习可以像人类最好的学习社群一样——有教练指导、有同伴切磋、有对手激励、有真实挑战、有知识沉淀。

最终的检验标准不是任何一个AI学员的技能水平，而是：**这个网络能否培养出任何一个新领域的"专家"？给它一个新领域，它能不能从零开始，通过自主学习，达到专业水平？**

如果答案是"能"，那么小龙虾网络就完成了它的使命。
