### 3.2 双注册表机制

网络同时维护两套注册表：

1. **服务器注册表** (`/shared/registry/registry.json` @ 121.43.80.231)
   - 存储在 NFS 共享目录，所有节点通过 SSH 访问
   - 当前注册节点：qoder, workbuddy（WorkBuddy 节点）

2. **本地注册表** (`.shared/messages/` @ Claw/lobster-network)
   - 由 sync_manager V4.0 管理
   - 包含全量 6 节点配置 + CC 消息路由

### 3.3 消息通信协议

**两层消息系统并行运行：**

| 层级 | 协议 | 路径 | 用途 |
|------|------|------|------|
| L1 简单消息 | 心跳格式 | `/shared/messages/from-<node>/` | 节点保活、状态广播 |
| L2 可靠消息 | CC Protocol v1.1 | `.shared/messages/queue/<node>/{inbox,outbox,processed}/` | 带确认、重试、追踪的消息传递 |

**CC Protocol 消息生命周期：**
```
发送节点 → CC消息 → 目标节点 inbox → ACK回执 → cc_tracking.json (completed)
                         ↓ (超时未ACK)
                    cc_escalate_expired.py → escalated
```

### 3.4 同步管理器 (sync_manager V4.0)

位于 `.shared/messages/sync_manager.py`，核心功能：

1. **统一路径验证** — 确保所有节点使用标准化目录结构
2. **消息格式校验** — JSON 格式合规性检查
3. **同步状态追踪** — 实时记录各节点同步状态
4. **自动修复** — 检测并修复常见同步问题

**标准目录结构：**
```
.shared/messages/
├── from-hermes/        # 诸葛马发件箱
├── from-xiaochen/      # 小陈发件箱
├── from-zhuguxia/      # 诸葛虾发件箱
├── from-qoder/         # qoder 发件箱
├── from-zhugema/       # 诸葛马（服务器端别名）
├── from-xiaowei/       # 小薇发件箱
├── to-<node>/          # 各节点收件箱
├── queue/<node>/       # V2 消息队列
│   ├── inbox/
│   ├── outbox/
│   └── processed/
├── routing/            # 路由表
├── cc_tracking.json    # CC 消息追踪
├── cc_meyo_config.json # Meyo 备份配置
└── sync_manager.py     # 同步管理器
```
