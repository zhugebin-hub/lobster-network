## 二、方案B：学员询问 + 模拟

### 测试配置
| 项目 | 配置 |
|------|------|
| 通信 | V4.0消息系统(SCP+轮询器) |
| 棋盘 | 19×19 |
| 黑方 | 小陈(稳健型-特征模拟) |
| 白方 | 诸葛虾(加速型-特征模拟) |
| 手数 | 60手 |

### 通信测试结果
| 学员 | 消息发送 | ACK回复 | 实际落子 |
|------|----------|---------|----------|
| 小陈 | ✅ | ✅ (15秒内) | ❌ 未回复坐标 |
| 诸葛虾 | ✅ | ✅ (15秒内) | ❌ 未回复坐标 |

### 模拟对局结果
| 指标 | 小陈(黑) | 诸葛虾(白) |
|------|----------|------------|
| 角部着法 | 63% | 56% |
| 中腹着法 | 36% | 43% |
| 提子 | 3 | 0 |
| 风格 | 偏保守(角部多) | 偏激进(中腹多) |

### 优点
- ✅ **通信链路打通**: V4.0消息系统端到端验证通过
- ✅ **ACK机制可靠**: 两位学员均在30秒内ACK
- ✅ **特征模拟合理**: 小陈角部63% vs 诸葛虾56%体现差异

### 缺点
- ❌ **学员无实际落子**: 轮询器只ACK不执行围棋AI
- ❌ **依赖人工**: 需要用户手动回复坐标
- ❌ **延迟高**: 15秒轮询周期 + 人工响应时间

## 四、关键发现

### 1. 消息系统V4.0验证通过 ✅
- 教练→学员: SCP推送成功
- 学员→教练: ACK自动回复
- 端到端延迟: <30秒
- 两位学员均在线且响应正常

### 2. AI引擎可用 ✅
- 9x9和19x19均正常运行
- 规则完整(气/提子/Ko/禁着)
- 角部偏好合理(52%)
- 有提子战斗(黑3白11)

### 3. 学员端需要集成AI引擎 ⚠️
- 轮询器只处理消息并ACK
- 需要增加 `go_move_ask` → 调用AI引擎 → 回复坐标 的链路
- 这是方案A和B的融合点

---

## 五、推荐方案：A+B融合

```
学员端消息轮询器
  ├── 收到 go_move_ask 消息
  ├── 调用 go_ai_engine_v1.py 生成落子
  ├── 回复坐标到 from-{student}/
  └── 教练端收集 → 裁判 → 通知对手
```

**优势**:
- 全自动(方案A) + 学员特征(方案B)
- 无需人工干预
- 可评估真实学员水平(接入真实AI棋力)
