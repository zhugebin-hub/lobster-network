## 二、根因分析

### 2.1 为什么训练完成率逐日下降？

**不是学员不努力，是系统架构有根本缺陷：**

| 问题 | 根因 | 影响 |
|------|------|------|
| 提交目录为空 | 学员端脚本运行但结果未正确写入outbox | 教练无法获取训练数据 |
| 训练被挤占 | 基础设施任务（V3.0测试/文档）占用训练窗口 | Day3全员未提交 |
| 同步通道报错 | Python 3.6不兼容 `capture_output` 参数 | qoder同步失败 |
| 消息消费断链 | 学员端无持久化消息轮询，脚本重启后丢失 | 任务发出但学员不知 |

### 2.2 为什么执行力普遍偏低（20-50分）？

1. **任务分发→执行→提交链路断裂**：教练发消息→学员脚本收到→解题→结果写入outbox→教练读取，任一环节出问题都导致"无提交"
2. **缺乏强制提交机制**：学员解题后结果存在内存/本地，但未强制推送到共享目录
3. **无提交验证**：教练无法确认学员是否真的完成了训练

### 2.3 为什么小陈推理力仅35分？

- 高级题准确率仅35%（远低于入门90%）
- 倒扑/扑区分不清（基础手筋概念混淆）
- 缺乏分步推理训练方法
- 训练量大但质量低（10,337题但高级题不足）

## 三、优化方案

### 3.1 系统架构优化（紧急）

#### 🔧 修复1：端到端提交验证机制

```
当前流程：
  教练发消息 → 学员解题 → 写入outbox → 教练读取
  ❌ 问题：中间环节无验证，写入失败无感知

优化后：
  教练发消息 → 学员解题 → 写入outbox → 学员回传ACK确认 → 教练验证 → 教练回ACK
  ✅ 每个环节都有确认和超时重试
```

**具体措施：**
- 学员解题后立即写入outbox，并回传 `submission_ack` 消息
- 教练收到ACK后验证文件内容，回传 `coach_ack`
- 超时未收到ACK自动触发催促（soft→medium→hard→escalate四级）
- 提交文件增加校验和（checksum）防止损坏

#### 🔧 修复2：训练时间保护机制强化

```python

# 优化：在调度器中增加时间窗口检查

TRAINING_WINDOWS = [
    (8, 12),   # 上午训练
    (14, 18),  # 下午训练
    (19, 22),  # 晚上训练
]

def can_run_task(task_type, current_hour):
    in_training = any(start <= current_hour < end for start, end in TRAINING_WINDOWS)
    if in_training:
        return task_type in ("training", "critical")
    return True  # 非训练窗口允许所有任务
```
