## 一、为什么从 NFS 升级到 MCP？

| 对比项 | NFS 文件通信（旧） | MCP Server（新） |
|--------|-------------------|-----------------|
| 通信方式 | 文件读写 + 轮询 | SSE/WebSocket 实时流 |
| 延迟 | 30秒~数分钟 | 毫秒级 |
| 消息可靠性 | 无确认机制 | 标准确认/重试 |
| 扩展性 | 需手动建目录 | 协议天然支持多Client |
| 路由能力 | 手动约定文件名 | 标准 Tool/Resource 路由 |
| 跨网络 | 依赖NFS内网挂载 | SSE 可跨公网 |
| 生态兼容 | 私有协议 | Anthropic 标准协议 |

## 三、核心组件

### 3.1 MCP Router Server（路由中枢）

**位置**: `/lobster-ecosystem/router/mcp_router_server.py`

**核心功能**:
- **服务注册**: 各小龙虾启动时注册自身 ID、名称、角色、能力列表
- **消息路由**: 根据消息类型 + 内容匹配路由规则，自动分发到目标服务
- **消息持久化**: SQLite 存储所有消息，支持状态追踪（pending → delivered → acked）
- **心跳检测**: 定期更新服务在线状态，离线服务不分配任务
- **优先级调度**: urgent > high > normal > low，高优先级消息优先处理

**10个标准 Tool**:
| Tool | 功能 |
|------|------|
| `register_service` | 注册小龙虾服务 |
| `heartbeat` | 发送心跳保活 |
| `send_message` | 发送消息（自动路由） |
| `receive_messages` | 收取待处理消息 |
| `ack_message` | 确认消息已处理 |
| `list_services` | 列出所有服务 |
| `get_stats` | 获取路由统计 |
| `add_route_rule` | 添加路由规则 |
| `get_message` | 查询消息详情 |
| `list_messages` | 列出消息历史 |

### 3.2 MCP Go Training Server（围棋训练服务）

**位置**: `/lobster-ecosystem/go-training/mcp_go_training_server.py`

**功能**: 将原有 `/shared/training/go/` 文件系统围棋训练系统封装为 MCP Server

**12个标准 Tool**:
| Tool | 功能 |
|------|------|
| `get_training_status` | 获取训练系统整体状态 |
| `get_player_profile` | 获取学员档案 |
| `get_player_progress` | 获取学员进度 |
| `get_daily_log` | 获取训练日志 |
| `submit_training_result` | 提交训练结果 |
| `start_match` | 发起对局 |
| `submit_move` | 提交落子 |
| `get_match_status` | 获取对局状态 |
| `list_matches` | 列出对局记录 |
| `get_problem_bank_stats` | 题库统计 |
| `update_training_config` | 更新训练配置 |
| `get_ecosystem_training_overview` | 生态视角训练总览 |

### 3.3 小龙虾 Client（各智能体）

每个小龙虾作为 MCP Client 连接 Router Server：
- 启动时调用 `register_service` 注册自身
- 定期调用 `heartbeat` 保持在线
- 通过 `send_message` 发送消息（自动路由）
- 通过 `receive_messages` 收取待处理消息
- 处理完成后调用 `ack_message` 确认

## 四、消息路由规则

**位置**: `/lobster-ecosystem/router/router.db` → `route_rules` 表

**默认规则**（9条）:
| 模式 | 目标 | 优先级 | 说明 |
|------|------|--------|------|
| `go_training_task` | xiaochen | 10 | 围棋训练任务→小陈 |
| `go_training_result` | hermes | 10 | 训练结果→诸葛马 |
| `go_match_request` | hermes | 10 | 对局请求→诸葛马 |
| `go_review` | hermes | 8 | 复盘→诸葛马 |
| `review_request` | hermes | 10 | 审核请求→诸葛马 |
| `strategic_planning` | hermes | 10 | 战略规划→诸葛马 |
| `broadcast` | * | 1 | 广播→所有 |
| `*` | hermes | 0 | 默认→诸葛马 |

**路由匹配逻辑**:
1. 精确匹配消息类型
2. 模式匹配（支持 `*` 通配）
3. JSONPath 风格内容匹配（如 `$.category`）
4. 默认兜底规则

## 五、消息生命周期

```
发送方                    Router Server                 接收方
  │                           │                           │
  │── send_message ─────────→│                           │
  │   (创建 pending 消息)     │                           │
  │                           │                           │
  │                           │── 路由匹配 ──→ 目标服务     │
  │                           │                           │
  │                           │  ◄── receive_messages ───│
  │                           │   (获取 pending 消息)      │
  │                           │                           │
  │                           │── 标记 delivered ──→      │
  │                           │                           │
  │                           │   [接收方处理业务逻辑]      │
  │                           │                           │
  │                           │  ◄── ack_message ────────│
  │                           │   (确认已处理)            │
  │                           │── 标记 acked ──→          │
  │                           │                           │
```

**消息状态**: `pending` → `delivered` → `acked`

## 八、与 NFS 兼容

MCP 架构启动后，NFS 通道保留为**备份通信方式**：
- 主要通信走 MCP Router（实时、可靠）
- NFS 文件作为消息归档和离线备份
- 双通道并行运行，确保消息不丢失
- 稳定后逐步关闭 NFS 写入，仅保留读取
