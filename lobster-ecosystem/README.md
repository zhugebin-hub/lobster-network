> **核心融合**: 案例002「递归自主式分解与人机协作新范式」+ MCP 路由中枢  

---

##  架构核心

**用户无感知**：用户只与入口小龙虾（虾尔）交互，不感知后端路由和分解

**能力自注册**：业务小龙虾启动时自动向 Router 注册能力画像（成本/速度/质量）

**递归分解驱动路由**：Router 不是简单转发，而是理解任务→分解→匹配→协调

**MCP 标准协议**：基于 Anthropic MCP 标准，天然兼容多智能体生态

---

##  整体流程

```
用户（自然语言）→ 虾尔（入口）→ MCP Router（递归分解）→ 业务小龙虾（执行）→ 虾尔（聚合回复）
```

### 三层架构

```
第一层：递归分解层 → 理解任务意图 → 分解为元业务 → 提取约束
第二层：动态匹配层 → 能力画像查询 → 约束剪枝 → 最优执行者选择
第三层：执行协调层 → MCP消息分发 → 进度跟踪 → 结果聚合
```

---

##  四种人机协作模式

| 模式 | 名称 | 适用场景 |
|------|------|----------|
| A | 纯AI执行 | 标准化、低风险任务（死活题批改、日程管理） |
| B | AI执行+人工审核 | 重要但可自动化的任务（黑客松评审、教学分析） |
| C | 人工主导+AI辅助 | 创造性、高价值任务（论文撰写、战略规划） |
| D | 人机并行 | 复杂多步骤任务（围棋对局、端到端研究报告） |

---

##  能力画像体系

每个小龙虾三维量化：**成本**（越低越好）+ **速度**（越高越快）+ **质量**（越高越好）

综合评分 = 质量×40% + 速度×30% + (1/成本)×20% + 能力匹配度×10%
